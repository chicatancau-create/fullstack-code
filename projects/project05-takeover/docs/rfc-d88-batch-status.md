# D88 RFC：任务批量状态更新

## 问题

接手后的工作区任务只能逐条 `PATCH /tasks/:taskId`。一次调整 10–50 条任务会产生同样数量的 HTTP 请求，
失败项与成功项混在一起，调用方无法可靠重试。

## 非目标

- 不实现批量创建/删除任务。
- 不实现跨工作区批量操作。
- 不引入队列、异步任务或版本号。

## 候选

1. **全有或全无**：任一失败整批回滚。调用方处理简单，但一个非法 id 会拖垮整批。
2. **逐项结果**：每项独立事务，返回 `ok/error` 与 `changed`。调用方可只重试失败项；实现更复杂。

选择 2。50 条上限保证请求有界；每项用行锁事务，状态变更与审计同事务提交。

## 契约

`PATCH /workspaces/:id/tasks/batch`

```json
{ "updates": [ { "id": 12, "status": "done" }, { "id": 13, "status": "doing" } ] }
```

- 非成员：404，不泄露工作区是否存在。
- `updates` 非数组、空或超过 50：400 `invalid_updates`。
- 单项非法：`{ id, ok:false, error:"invalid_id"|"invalid_status"|"not_found" }`。
- 合法项：`{ id, ok:true, status, changed }`；同状态重复提交 `changed:false`，不写审计。
- 跨工作区 task id：逐项 `not_found`，不修改数据。

## 影响与风险

- 新增路由，旧单条接口保持不变；单条接口现在也写 `p02.task_events`。
- 每项一个事务，50 项最多 50 次提交；D90 已比较逐条与集合更新，集合更新仅用于性能对照，不改接口语义。
- 回滚：删除路由并回退 `src/app.js`；`task_events` 表可保留（追加表，不影响旧路径）。

## 验收

- 正常、非法项、跨租户、超限、幂等五类测试。
- 审计行与状态变更同事务；失败项不产生审计。
