# ADR 0002：租户隔离与最后 Owner 用父行锁

- 状态：接受
- 日期：2026-11-07

## 背景

工作区是多租户边界；任何成员变更都必须保证至少一个 Owner。两个 Owner 同时删除自己会产生写偏差。

## 选项

1. 应用层先 count 再删：两个事务都看到 2，最终 0（E07 已复现）。
2. 锁 workspace 父行 `SELECT ... FOR UPDATE`，串行化成员变更，再 count/删。
3. Serializable + 重试：数据库检测冲突，应用重试；实现更复杂。

## 决定

采用 2。所有成员增删/角色变更先锁 `p02.workspaces` 同一行；读路径用 membership JOIN 限定租户。

## 代价

- 同一工作区的成员变更串行；跨工作区不互相阻塞。
- 锁顺序必须统一（先 workspace），否则未来多资源操作仍可能死锁。
- 读路径没有行锁；权限撤销与已发出请求之间仍有短窗口。

## 验证

`tests/app.test.js`：最后 Owner 删除/降级 409；两个 Owner 并发删除只有一个 204，另一个 409，最终 owner=1。E07 提供写偏差复现对照。
